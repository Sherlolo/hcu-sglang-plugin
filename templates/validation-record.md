# 能力验证记录模板

> **用途**：复制后记录一次能力/版本组合的实际结果，按影响面填写适用项；空白或历史结果不是本次通过。状态沿用 passed / failed / pending / not-applicable。方法入口见 [开发闭环](../docs/development-methodology.md)。

## 1. 接受配置与环境身份

| 项 | 本次值 |
|---|---|
| 日期 / 执行人 / 能力与需求 ID | |
| official / plugin 路径、branch、SHA、dirty | |
| adapter（使用时）的 SHA、声明依赖与组合 | |
| checkpoint/revision、tokenizer/template、reasoning/tool 协议 | |
| 原配方路径/SHA256；派生配方路径/SHA256 | |
| 用户授权的配置差异（如有）/适用接受行 | |
| 物理设备、可见性映射、NUMA、进程内可见数 | |
| 镜像 tag/digest、挂载、Python realpath、Torch/DTK/vendor | |
| 实际 builder 环境、工具链版本、扩展 fingerprint/ABI | |
| 当前证据目录与长期保留位置 | |

诊断改变的 Graph、backend、dtype 或拓扑另列，不能替代原接受行。仅在适用时填写构建/设备字段，不为纯文档或 CPU 工具任务占 GPU。

## 2. 调用链和所有权

| 目标/阶段 | 实现与实际文件 | caller / consumer / readout | 参数、返回、dtype/stride/scale | 状态写入 / sum / 释放 owner | 停用后的有效基线 |
|---|---|---|---|---|---|

记录生产者返回局部贡献还是已完成结果、group 与预期次数；不要仅写“已包装”。pending/缓存状态注明由哪条真实生命周期产生。

## 3. 假设、反例与修复

| 假设或分叉 | 对齐的输入/状态与实际分支证据 | 修复前失败与 oracle | 最小变更/SHA | 修复后同一断言 | 对原接受配置的复验 |
|---|---|---|---|---|---|

警告、不同 shape 的失败或同名实现通过先作为线索。没有复现的试验说明去留；ABI/阈值按当前依赖解释，不静默放宽。已执行失败的对照保留 failed，不能改成“对照成功”或从接受矩阵消失。

## 4. 分层与形态矩阵

| 需求 / lane / 产物形态 | 必测/可选与理由 | 命令、版本和配置 | 断言/阈值与来源 | 状态 | 本次原始证据/哈希 | 未覆盖条件/解除条件 |
|---|---|---|---|---|---|---|

接线分别记 AST / 注册 / apply / 实际命中，不合并为 active 数字。按变化选测真实构造、公共入口、实际 readout、TP>1、空/非空、状态与 Graph replay。源码、隔离 wheel/image、embedded 分开记录真实 import、包数据与行为；只要求一种形态时说明范围。

## 5. 服务运行与响应

| run-id / 接受或诊断行 | 会话/控制器、宿主/容器 PID、创建时间、进程组、等待截止 | owned listener / health / 实际模型名 | 原始响应及 SHA256、oracle/检查报告 | finish reason / token 数 / 最终答案 | 状态 / 失败签名 |
|---|---|---|---|---|---|

确定性短响应检查完整答案；思考段提取须明确协议，不搜索长文本中的数字。缓存/投机若为必测，分别保存实际命中/accepted 指标和正确输出。重复输入或用例命名不证明命中。

## 6. 资源、清理与重试关系

| run-id | 启动前显存/利用率/端口 | 实际进程身份/最近观察 | 自有清理与 remaining / 端口 / 占用 | 原因/后继 run-id |
|---|---|---|---|---|

失联或观察超时先核对原进程，不重复拉起。共享冲突若需处理，记录用户授权、GPU→PID→cgroup→容器归属、实际动作及权限结果；默认不操作他人服务。旧 failed/pending 不覆盖，后继独立通过单独关联。

## 7. 逐项结论

| 显式需求、命令、产物或必测行 | 证明它的本次证据 | 结论 | 剩余事项 |
|---|---|---|---|

按实际接受范围判断完成；必测 failed/pending 未闭合时不宣布完整通过。明确已验证/未验证的模型、并行、上下文、batch、回退及部署组合。记录指标时分开冷编译/预热/测量，报告正确性和同环境相对基线。

归档原始失败、修复、产物和最终响应；将真正改变决策的经验写入维护中的文档/skill。ignored 日志不是已提交的历史或已部署的自动监控。

## 8. HCU 逻辑对照（需求适用时）

| 当前 HCU SHA / 符号 | 插件实现与 embedded 文件 | 生成/来源哈希与预期集成映射 | caller/consumer 与适配差异 | 行为反例和本次证据 | 未迁移/未验证范围 |
|---|---|---|---|---|---|

分开结论：生成保真、来源保真、已验证行为、整个 fork 等价是否证明。源码不等不自动意味着行为错；AST、资源哈希或 apply 一致也不自动意味着全逻辑相同。
